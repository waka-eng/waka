Signals: inputs → patterns

Start with the current capture; related saves may add evidence.

1. Model inputs

Inputs and how WAKA uses them
InputWhat is actually passed
Current noteSaved text, up to 4,000 characters.
Capture contextsource (app/agent), createdAt, locale hint.
Answered reflectionsNon-skipped question + answer, up to 800 characters each.
AttachmentsReady page text, image description or transcript: kind, host/file label, 2,000 characters each. Corrected audio text replaces the original transcript.
Related inspirationsUp to 5: ID, date and 1,000 characters of saved text each. Related reflections/attachments are not sent.
Existing vocabularyUp to 500 current signal statements + 24 categories, for consistent wording and labels—not new evidence.

Follow the capture’s language; explicit author wording may be reused. A saved reference does not prove agreement.

2. Related-source selection

  • Embed text + kind + answered reflections + attachment text with Gemini Embedding 001; reuse unchanged vectors.
  • Scan up to 500 newest eligible stored vectors in the same profile, excluding this capture and records excluded from memory. Keep similarity ≥ 0.60; take up to five best matches.

3. Generate, check, save

  • Propose 0–3 statements grounded in the current capture, plus category, optional reason/quote and up to 2 related citations per statement.
  • Check meaning: same → add evidence; opposed → preserve conflict; different → new signal. Keep time limits and uncertainty.
  • Verify IDs and quotes. Owner quotes must match the note/reflection answer; related quotes must match that related note.
  • 3 independent current evidence units → active. Reprocessing adds no extra support. Confidence uses evidence, time, source variety and confirmation. Human edits stay locked.

Example: a prototype note + “I want to test first” + a related trial can support “I want to test before committing.” Two origins still count as two—not five retrieved votes.

Top of Mind: signals → a reading

Write from signals; check against original excerpts.

1. Select signals

  • Rank supported signals: 45% confidence + 20% support + 20% recency + 15% return. “Not true” multiplies the score by 0.4; reduce similar themes.
  • Aim for 12, including up to 3 recent focuses (14 days); emerging focus needs 2 witnesses. If fewer than 3 are selected, backfill with tentative emerging signals.
  • Keep opposing signals together, even if that exceeds 12.

2. Writer inputs

Inputs and how WAKA uses them
InputWhat is actually passed
Selected signalsID, statement, status, confidence, support count, evidence date/time pattern, opposing IDs and original inspiration IDs.
Existing reading & choicesCurrent text/citations, locked/pinned wording and support state, plus up to 20 recent verdicts/corrections.
LanguageSelected English/Korean; human-kept wording stays exact.
Original sourcesOriginal excerpts go to the later reviewer, not the writer.

3. Publication checks

  • Terra writes up to 7 typed entries with signal citations; optional belief/question. “No change” is allowed.
  • Each new entry needs 2+ distinct originals and fresh wording. Multiple signals from one source—or identical re-saves—do not add origins.
  • Code checks language, citations and copying. Terra reviews grounding/synthesis using up to 4 excerpts × 1,600 characters per entry, including note, reflection and attachment text.
  • Failures keep the previous valid reading; human-kept wording survives. Whole-reading semantic repetition detection remains disabled.

Timing: automatic evidence-driven changes wait 24 hours; first generation, manual refresh and language changes are exempt.

Example: small trials + concrete comparisons → “You’re exploring choices through tests and comparisons before committing.” Both original sources must support the connection.

Principles: patterns → choice rules

A reusable guide for future choices, not a summary or task.

1. Inputs & eligibility

Inputs and how WAKA uses them
InputWhat is actually passed
Supported active signalsID, statement, independent evidence count, first/last evidence dates and meaningful reading appearances. Save dates need not be experience dates.
What is already shownCurrent reading + existing principles: context to avoid repetition, not additional evidence.
Selection boundsUp to 48 signals + 24 principles + 7 entries, within 16,000 characters. Prioritize current-reading signals, then appearances, span and support.
Minimum for each candidate3 distinct supported active statements, collectively cited in 1+ meaningful reading. Duplicate wording counts once; no calendar wait.

2. Generate & validate

  • DeepSeek proposes 0–3 rules under 200 characters: type, statement, signal citations. Use the profile language and a reusable directive.
  • References ≠ endorsement; temporary plans ≠ lasting beliefs. Unrelated signals cannot be forced into one rule.
  • A separate check reads only the candidate and cited signal statements, not original excerpts. Reject unsupported motives, trade-offs or certainty.

3. Save & maintain

  • Compare with all standing principles: same → add citations; conflicting → flag; new → append. Failed comparison postpones saving.
  • Recheck source versions. Keep human edits and ordering. Lost evidence may remove machine rules; owner-written wording remains.
  • Owner declarations can start as aspirations without the automatic evidence bar.

Example: supported patterns about trials, alternatives and feedback → “Before committing, compare small trials and use real feedback.” This does not justify an added rule such as “pay more”.

Next: safeguards and current limits →

What is protected—and what remains open

Human ownership
New chat and personal MCP connections use your human profile. Retained legacy agent stacks and credentials stay isolated; no creation, switching or merging.
Human edits stay
Edits lock generated wording. Pins, dismissals, and locks survive regeneration. Feedback applies to the wording reviewed.
Source changes matter
Edits and deletions recheck support. Stale jobs cannot overwrite newer material; failed generation keeps the previous valid reading.
Restore & retries
Browser deletions: restore within 30 days. Legacy agent/API-key deletions remain permanent. Restore reprocesses memory; retries reuse the save identity.
No new regular DB pings
Bounded retries, budgets, and one-time wakeups recover known work. Existing daily maintenance remains.

Current product limits

  • Chat media: the reply model does not read direct chat attachments.
  • Repetition: the semantic comparison experiment is off. Reworded repetition may still occur.
  • Audio: Gemini remains active after Voxtral missed part of a mixed Korean/English recording.

Before public launch

Owner alert delivery, central browser-error reporting, and reliable deleted-file cleanup still need to be completed and exercised before public launch.

Team decisions

Refine evidence, generation, chat and MCP.

Current rules → open questions. The options below are not approved changes.

Seven decisions

Memory, chat and MCP decisions
AreaCurrent behavior → open decision
1 · Inspiration types

Current: Basic capture kinds do not distinguish authorship or endorsement.

Decide: Separate format, author, copy/summary and stance? Which labels need user confirmation?

2 · Signal creation

Current: Up to 5 related captures; 3 independent evidence units to activate.

Decide: What counts as independent support? Refine source weighting, matching and activation thresholds.

3 · Top of Mind

Current: 2+ distinct originals per entry; 24-hour automatic-update wait.

Decide: What is useful synthesis? Set novelty, repetition, refresh triggers, and reflection vs action guidance.

4 · Principle creation

Current: 3 supported active signals + meaningful reading history.

Decide: When is a pattern a lasting choice rule? Handle temporary plans, conflicts and borrowed advice.

5 · Chat prompts

Current: Relevant memory, latest correction, at most one follow-up; no auto-save.

Decide: When to answer, reflect or ask? Improve relevance, tone, citations and responses without useful memory.

6 · MCP thresholds & filters

Current: Recall: fixed similarity ≥ 0.60, up to 8 results—not a confidence score. Saves have no similarity gate.

Decide: Presets or custom thresholds? Filters by support, date, type or endorsement? Define auto-save and duplicate rules separately.

7 · MCP save destination

Current: New personal connection consent selects human memory only. Existing profile-bound credentials stay scoped; source="app" never changes ownership.

Discuss: Make personal connection consent and intentional saves understandable while preserving one companion and the isolated legacy boundary.
