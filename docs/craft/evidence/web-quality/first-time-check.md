# WAKA first time usability check

Use five people who have not used WAKA before, on the candidate build with
synthetic data. Use participant IDs P1–P5. Record the build, viewport and locale.
Do not enter real memories or publish anything during this check.

Give one task at a time. Read only the task, without button names or gestures.
Let the participant think aloud. Record their first action, hesitation, wrong
turns, completion and requests for help. If you give help, mark completion as
assisted. An agent walkthrough does not count as a participant.

1. Keep this privately: “I want a little room for an unfinished idea.” Start
   another thought, close it unfinished, then return to it.
2. Find something saved earlier, revisit it, then move on while keeping it.
3. Find the guides WAKA has gathered for making choices.
4. Begin a conversation about one of those guides.
5. Prepare an image of a guide to share, keeping its saved words unchanged.
   Stop at the preview or download; do not publish it.

Afterward ask what was saved, what remained a draft, and whether a reading that
is still processing changes the save result. Ask which action felt least clear.
Record the participant's explanation without correcting it during the tasks.

Use an empty synthetic account for task 1 and a returning synthetic account
with seeded inspirations and guides for tasks 2–5. Explain the transition as a
change of sample account, without explaining how to perform the tasks. Clear
only that participant's disposable data afterward.

Target: at least four of five participants complete each task unaided, with
zero accidental public shares or deletion through navigation. Keep failed
observations, repair recurring confusion and repeat the affected tasks with
new participants. This formative check does not estimate population-wide success.
Results remain pending until actual observations are supplied.
