# WAKA 오늘의 리뱀프 — 코딩 에이전트 작업 지시서

> **오늘의 원칙: 새 걸 짓지 말고, 이미 있는 두 메커니즘을 보이게 만든다.**
> lock과 근거 추적은 이미 WAKA의 스펙에 존재한다("사람이 고친 문장은 덮어쓰지 않는다", "근거와 confidence만 갱신된다"). 오늘은 이 배관을 **별**과 **뿌리**라는 signature 경험으로 승격한다.

---

## 0. 컨텍스트 — 에이전트가 알아야 할 최소한

- WAKA는 사람과 AI 에이전트가 함께 쓰는 기억 시스템. 4층 구조: **inspiration**(가공 전 기록, field의 orb) → **signal**(반복 패턴, sky에 떠 있음) → **top of mind**(현재 중요한 것의 버전 문서) → **principle**(상황이 바뀌어도 남는 기준).
- 시장 리서치 결론: 플랫폼 메모리(ChatGPT 등)의 1위 불만은 **"기억은 하는데 틀리게 기억하고, 어디를 고쳐야 하는지 찾을 수 없다"**. 전체 목록·출처·영향이 안 보이는 audit gap이 가장 검증된 공백이다.
- 언어 원칙: **같은 뼈대, 세 사투리.** 데이터·API는 지루한 인프라 영어, UI는 들판·하늘 우주의 WAKA 언어(한국어), 영업·기술 문서는 다시 인프라 영어. 상세는 Task 0의 GLOSSARY.
- ⚠️ 이 문서는 리포 실제 구조를 모른 채 작성됐다. 파일 경로·모델명·컴포넌트명은 실제 구조에 맞게 조정하되, **의미와 acceptance criteria는 유지**할 것. 스펙과 코드가 충돌하면 작업을 멈추고 사람에게 보고.

## 1. 전역 규칙 — 모든 태스크에 적용

1. **GLOSSARY.md가 네이밍의 single source of truth.** Task 0에서 생성 후 모든 PR에서 준수.
2. **방언 경계:**
   - 데이터 모델·API·DB 컬럼 → 인프라 영어만 (`locked`, `sources`, `versions`). **은유 금지.** `star`, `root` 같은 식별자를 데이터 레이어에 쓰지 말 것.
   - UI 컴포넌트·프레젠테이션 레이어 → 은유 허용 (`StarBadge`, `RootsPanel`, i18n 키 `ui.star.*`).
   - 사용자 노출 문자열(ko) → 은유 사용 시 반드시 맨말 한 줄 동반(아래 4번).
3. **UI 문자열 금지어:** 잠금, lock, 출처, provenance, 버전, version, 감사, audit, 히스토리. (설정 화면의 법적 고지, 개발자 문서는 예외 — 예외 사용 시 코드 주석으로 사유 명시.)
4. **엄마 테스트:** 모든 은유 요소는 hover(데스크톱) 또는 tap/ⓘ(모바일)로 맨말 한 줄 설명이 떠야 한다. 시는 첫인상, 명료함은 신뢰.
5. 은유는 **들판/하늘 우주에서만** 가져온다. 새 은유가 필요하면 GLOSSARY에 먼저 추가한 뒤 사용.
6. 브랜치: `revamp/stars-and-roots`. 커밋 prefix: `glossary:` `schema:` `star:` `roots:`.
7. 각 Task 완료 시 acceptance criteria 체크리스트를 PR 설명에 복사해 체크 상태로 첨부.

## 2. Task 0 — GLOSSARY.md 생성 (최우선, ~30분)

리포 루트에 아래 블록 내용을 **그대로** `GLOSSARY.md`로 저장한다.

```markdown
# WAKA GLOSSARY — 같은 뼈대, 세 사투리

WAKA의 모든 이름은 이 문서를 따른다. 새 개념에 이름이 필요하면 이 표에 먼저 추가한다.

## 원칙

1. **은유는 한 우주에서만.** WAKA의 우주는 들판과 하늘이다. 별, 뿌리, 계절, 모닥불, 문, 노을 — 전부 여기서 나온다. 다른 세계의 은유(금고, 잉크, 영수증)를 섞지 않는다.
2. **이름은 사용자가 만지는 것에만.** 내부 동작(예: 최신 사실 우선 등)은 이름 없이 "조용한 올바름"으로 존재한다. 만든 단어가 많아지면 시가 아니라 수수께끼가 된다.
3. **방언 경계.** 데이터·API = 인프라 영어 / UI = WAKA 언어(ko) + 맨말 / 영업·기술 문서 = 인프라 영어. 셋은 같은 기능의 다른 이름이다.
4. **엄마 테스트.** 모든 은유는 hover/tap 한 줄로 설명 가능해야 한다. 아래 표의 "맨말"이 그 한 줄이다.

## 번역표

| 개념(메커니즘) | 데이터·API (영어, 지루하게) | UI (ko) | UI 맨말 한 줄 | 문서·영업 (en) | 상태 |
|---|---|---|---|---|---|
| 사용자 고정 문장 | `locked: boolean`, `locked_at` | **별** | 내가 직접 쓴 문장 — WAKA가 다시 쓰지 않아요 | User-locked immutable statement (immutable override) | **오늘** |
| 근거 링크 | `sources: SourceRef[]` — `record_id`, `excerpt`, `linked_at` | **뿌리** | 이 signal이 자란 기억들이에요 | Provenance (evidence links) | **오늘** |
| 버전 보존 | `versions[]` (soft-invalidate, 삭제 없음) | **계절** | 지난 계절의 나 — 지워지지 않고 남아요 | Version history (invalidate-don't-delete) | 예약 |
| 공유 공간 | `space`, `membership` | **모닥불** | 함께 지피는 기억이에요 | Governed shared spaces | 예약 |
| 접근 제어 | `permissions` | **문** | 누구에게 어떤 문을 열지 정해요 | Access control | 예약 |
| 소멸·은퇴 | `dormant_at` | **지다** | 오래 안 쓰인 signal은 노을처럼 져요 | Decay / retirement policy | 예약 |
| 행동 귀속 | `decision_trace` | **선택의 뿌리** | 이 선택이 어느 기억에서 왔는지예요 | Attribution / decision audit | 예약 |

## UI 금지어

잠금, lock, 출처, provenance, 버전, version, 감사, audit, 히스토리.
예외: 설정 화면의 법적 고지, 개발자용 문서. 예외 사용 시 주석으로 사유를 남긴다.
```

**Acceptance criteria**
- [ ] 리포 루트에 `GLOSSARY.md` 존재, 표 6열 유지
- [ ] `README.md`에서 GLOSSARY 링크
- [ ] 에이전트 지침 파일(`CLAUDE.md` 또는 `AGENTS.md`, 있다면)에 "네이밍은 GLOSSARY.md 준수" 한 줄 추가

## 3. Task 1 — 스키마 게이트 (조사만, ~30분, 코드 변경 없음)

**질문 하나에 답한다: signal → 근거 기록 링크가 지금 저장되고 있는가?**

- 확인 대상: signal의 모델/테이블/타입 정의, signal을 생성·갱신하는 파이프라인 코드.
- **판정 A — 링크가 이미 저장됨:** Task 2(별)와 Task 3(뿌리)을 병행한다. Task 3은 순수 UI 작업이 된다.
- **판정 B — 링크가 없음:** 오늘은 Task 3(스키마 + 파이프라인 + UI)에 집중하고 Task 2는 내일로 민다. **뿌리가 기초 골격이다** — 별의 근거 표시, 계절, 선택의 뿌리(attribution)가 전부 이 링크 위에 올라간다.
- 산출물: 판정 결과 + 근거가 된 파일 경로를 `docs/notes/2026-08-22-schema-gate.md`에 기록하고 PR 설명에 요약.

판정 B일 때 권장 스키마(실제 컨벤션에 맞게 조정):

```
Signal {
  ...기존 필드,
  sources: SourceRef[],      // 근거 기록 링크 (신규)
  confidence: number,        // 이미 있으면 유지
  locked: boolean,           // 이미 있으면 유지
  locked_at?: timestamp
}

SourceRef {
  record_id: string,         // inspiration 기록 id
  excerpt?: string,          // 근거가 된 발췌 1~2줄
  linked_at: timestamp
}
```

- 마이그레이션: 기존 signal은 `sources: []` 허용. 빈 상태 UX는 Task 3-4에서 처리. **기존 데이터 백필은 오늘 금지**(§7 보류 목록).

**Acceptance criteria**
- [ ] 판정 A/B가 근거 파일 경로와 함께 문서화됨
- [ ] (판정 B) 스키마 변경 + 마이그레이션이 별도 커밋(`schema:`)으로 분리됨

## 4. Task 2 — 별: lock을 경험으로

**전제 확인부터:** 사람이 편집한 문장을 재생성이 덮어쓰지 않는 메커니즘이 백엔드에 실재하는지 테스트로 확인한다. 없다면 즉시 보고 — 그 경우 오늘의 최우선은 이 메커니즘 자체의 구현으로 전환된다.

### 작업 항목

1. **편집 → 별 전환.** 사용자가 signal 또는 top of mind의 문장을 직접 수정하고 저장하는 순간 `locked=true`, `locked_at` 저장 + 별 상태로 시각 전환. 전환 애니메이션 0.4~0.8초, 과하지 않게 — 한 번 보면 기억되고 열 번 보면 안 지겨울 것.
2. **시각 언어.** 별 문장: 작은 별 glyph + 미세한 톤 차이. WAKA 생성 문장: 기본(구름) 톤. 기존 디자인 토큰 안에서 해결하고 새 컬러 시스템 도입 금지.
3. **맨말 툴팁.** 별 hover/tap → `"내가 직접 쓴 문장 — WAKA가 다시 쓰지 않아요"`. i18n 키: `ui.star.tooltip`.
4. **재생성 대비 가시화.** 재생성 실행 시 갱신되는 문장들은 짧은 리라이트 효과, 별 문장은 정지 — **대비가 한눈에 보여야 한다.** 완료 토스트: `"하늘을 다시 그렸어요 — 별 {n}개는 그대로예요"`.
5. **문자열 sweep.** UI 전체에서 금지어를 검색해 GLOSSARY 언어로 치환. 치환이 애매한 문맥은 고치지 말고 목록으로 보고.
6. **별 해제.** 컨텍스트 메뉴 `"다시 WAKA에게 맡기기"` → `locked=false`. 확인 다이얼로그 1회, 맨말: `"이 문장을 WAKA가 다시 쓸 수 있게 돼요"`. unlock이라는 단어는 어디에도 노출하지 않는다.
7. **백엔드 계약을 테스트로 고정.** 재생성 파이프라인이 `locked=true` 문장의 **텍스트는 스킵**하되 근거·confidence는 계속 갱신하는지 자동 테스트로 못 박는다.

### Acceptance criteria
- [ ] 편집 저장 → `locked` 저장 + 별 시각 전환
- [ ] 재생성 3회 후에도 별 문장 텍스트 byte-동일, 주변 문장은 갱신됨 — 자동 테스트 포함
- [ ] 별 문장의 confidence·근거는 갱신 가능, 텍스트만 불변
- [ ] 툴팁 맨말 노출 (모바일 대체 인터랙션 포함)
- [ ] UI 문자열 금지어 0건 (`grep` 결과를 PR에 첨부)
- [ ] "다시 WAKA에게 맡기기" 플로우 동작
- [ ] 새로고침·재로그인 후에도 별 상태 유지

### QA 시나리오
1. 문장 편집 → 별 → 재생성 3회 → 문장 불변 확인
2. 별 해제 → 재생성 → 문장 변경됨 확인
3. 별 2개 + 일반 문장 3개 상태에서 재생성 → 토스트 카운트 "별 2개" 정확

## 5. Task 3 — 뿌리 v1: 근거를 경험으로

### 인터랙션 스펙

1. **뿌리 내리기.** sky의 signal 클릭 → field에서 근거 기록 orb 2~3개 하이라이트 + signal→orb 연결선("뿌리") 드로잉. 나머지 orb는 dim. 연결선은 위→아래로 자라는 짧은 드로잉 애니메이션.
2. **근거 패널.** 사이드 패널 또는 바텀시트. 리드 문장: `"이 signal은 이 기억 {n}개에서 자랐어요"`. 각 기록: 발췌 1~2줄 + 날짜. 기록 클릭 시 원본으로 이동.
3. **최단 수정 동선.** 뿌리를 보는 상태에서 바로 "문장 고치기"로 진입 가능해야 한다. **틀린 기억 발견 → 근거 확인 → 수정 → 별** — 이 동선이 §6 데모의 핵심 경로다.
4. **빈 상태.** `sources`가 빈 기존 signal: `"이 signal의 뿌리는 아직 기록되지 않았어요"` 표시. 백필은 별도 이슈로 생성만 하고 구현 금지.
5. **백엔드 (판정 B일 때).** signal 생성·갱신 파이프라인에서 근거 기록 id(+발췌)를 `sources`에 저장. 파이프라인이 이미 근거를 참조해 signal을 만들고 있다면 **그 id를 흘려보내기만 하면 된다** — 새로운 판단 로직 추가 금지.

### Acceptance criteria
- [ ] signal 클릭 → 뿌리 시각화 + 근거 패널, 체감 300ms 이내
- [ ] 발췌·날짜가 원본 기록과 일치 (수동 대조 3건)
- [ ] 빈 상태 문구 처리
- [ ] 뿌리 패널에서 문장 수정 진입 가능
- [ ] (판정 B) 신규 생성 signal에 `sources` 저장됨 — 자동 테스트 포함
- [ ] dim/하이라이트 대비가 접근성 기준(WCAG AA) 통과

## 6. Definition of done — 30초 데모

화면 녹화 30초 이하, PR에 첨부. **여섯 장면이 전부 나오면 오늘 성공, 하나라도 없으면 머지 금지.**

1. sky에서 틀리게 기억된 signal 발견 — 예: "회를 싫어한다"
2. 클릭 → 뿌리가 내려가고, 근거 기록 중 "감기 걸린 날, 오늘은 회 말고" 발췌 확인
3. 문장 수정: "회를 좋아한다 — 아픈 날은 예외"
4. 저장 순간 별로 전환
5. 재생성 실행 → 주변 문장은 다시 쓰이고, 별은 정지
6. 별 hover → 맨말 툴팁

이 30초가 플랫폼 다섯 개가 구조적으로 못 하는 것("기억을 고치고, 고친 것이 지켜지는 경험")의 전부이자, 앞으로 누구에게든 보여줄 첫 장면이다.
