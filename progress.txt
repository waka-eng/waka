# Ralph Progress Log

## Codebase Patterns

- WAKA is a pnpm workspace with API code in `packages/api`, web app code in `packages/web`, and Drizzle migrations under `drizzle/migrations`.
- Product direction for this run: WAKA becomes an ambition mirror powered by a personal context graph; use signal/context/top-of-mind language for new work.
- Keep the graph inspector internal. User-facing graph-backed output should appear as post-it-style Top of Mind notes, evidence drawers, patterns, and later decision memos.
- Signal-facing compatibility currently wraps existing `/api/inspirations` responses with additive `signal` and `signalScores` fields instead of renaming the route or persistence immediately.
- `meaning_nodes.type` remains a text compatibility field for now; use `contextNodeTypeValues` for new graph writes and `normalizeContextNodeType` when reading legacy `question`/`claim`/`life_direction` rows.
- Signal packet creation lives in `packages/api/src/lib/signal-packets.ts`, but persists to the existing `meaning_packets` table; `packages/api/src/lib/meaning-packets.ts` is a compatibility wrapper for old imports.
- Top-of-mind note compatibility lives in `packages/api/src/lib/top-of-mind-notes.ts`; it serializes current `wow_moments` rows into provisional active notes while persistence remains unchanged.
- The user-facing `/api/top-of-mind` route returns `topOfMindNotes` plus the legacy `topOfMind` preview field for current home-page compatibility; web client helpers live in `packages/web/src/lib/api.ts`.
- User feedback persistence lives in `packages/api/src/db/schema-feedback.ts` and `/api/feedback`; feedback targets are polymorphic, but create paths must verify target ownership for the signed-in tenant before inserting rows.
