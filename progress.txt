# Ralph Progress Log

## Codebase Patterns

- WAKA is a pnpm workspace with API code in `packages/api`, web app code in `packages/web`, and Drizzle migrations under `drizzle/migrations`.
- Product direction for this run: WAKA becomes an ambition mirror powered by a personal context graph; use signal/context/top-of-mind language for new work.
- Keep the graph inspector internal. User-facing graph-backed output should appear as post-it-style Top of Mind notes, evidence drawers, patterns, and later decision memos.
- Signal-facing compatibility currently wraps existing `/api/inspirations` responses with additive `signal` and `signalScores` fields instead of renaming the route or persistence immediately.
- `meaning_nodes.type` remains a text compatibility field for now; use `contextNodeTypeValues` for new graph writes and `normalizeContextNodeType` when reading legacy `question`/`claim`/`life_direction` rows.
- Signal packet creation lives in `packages/api/src/lib/signal-packets.ts`, but persists to the existing `meaning_packets` table; `packages/api/src/lib/meaning-packets.ts` is a compatibility wrapper for old imports.
- Top-of-mind note compatibility lives in `packages/api/src/lib/top-of-mind-notes.ts`; it serializes current `wow_moments` rows into provisional active notes while persistence remains unchanged.
- The user-facing `/api/top-of-mind` route returns `topOfMindNotes` plus the legacy `topOfMind` preview field for current home-page compatibility; web client helpers live in `packages/web/src/lib/api.ts`.
- User feedback persistence lives in `packages/api/src/db/schema-feedback.ts` and `/api/feedback`; feedback targets are polymorphic, but create paths must verify target ownership for the signed-in tenant before inserting rows.
- Top-of-mind refresh currently persists graph-generated notes through `wow_moments` with `top_of_mind_context_node:v1:*` idempotency keys until dedicated note persistence lands.
- Home should consume `fetchTopOfMindNotes` for the primary user-facing Top of Mind post-it surface; use the legacy `topOfMind` preview only as a fallback while compatibility remains.
- Web feedback submissions should use `createFeedback` from `packages/web/src/lib/api.ts`; top-of-mind note feedback targets use `targetType: "top_of_mind_note"` and the note id returned by `/api/top-of-mind`.
- Product-domain model calls should go through `packages/api/src/lib/model-provider.ts`; Gemini-specific HTTP clients remain the current implementation behind `gemini-model-provider.ts`.
- Capture highlights and lightweight resonance answers should travel through the existing `inspiration_sparks` request fields until a dedicated signal metadata table exists.
- The shareable Top of Mind value-prop surface currently lives at protected route `/top-of-mind/share` and reads the current user's notes from `/api/top-of-mind`; do not expose public note sharing until a share-token or permission model exists.
- Saved-signal archive and deep-dive UI should use the user-facing `/api/signals` route; it assembles legacy inspiration rows with signal packets, highlights, context nodes, top-of-mind notes, and signal feedback without making `/api/wow-moments` the preferred product surface.
- Final naming convention: product-facing UI, docs, model prompts, and web client helpers should use signal, signal packet, context graph/node, top-of-mind note, resonance, and feedback; `wow_*`, `meaning_*`, and `/api/wow-moments` names are legacy compatibility only unless a persistence migration explicitly renames them.
- Capture self-understanding metadata should use existing `inspiration_sparks.note` as `capture_metadata:v1:{...}` until a dedicated signal metadata table exists; signal packets already carry spark notes forward as user-provided evidence.
- Capture should remain one click away and quick-save capable, but the visible ritual should ask "What almost slipped away?", show local autosave safety near the writing area, and treat user highlights/resonance/micro-reflections as privileged evidence.
- Top of Mind post-its must help infer ambition and internal frequency. They should express desired environments, desired peers, work direction, taste/standards, rejected contexts, or emerging self-image. They must not be raw context-node labels, saved-signal summaries, tags, or shallow "You keep circling X" wrappers.
- Top-of-mind note surfaces should expose an `ambitionDimension` (`place`, `people`, `work`, `taste`, `tension`, `identity`, `rejection`, or `next_experiment`) so feedback validates the ambition read, not just a legacy WOW/context row.
- Home All Signals is now the primary saved-signal revisit surface; keep it in the Top of Mind shell and use `/signals` only as a compatibility/deep-link archive.
- Memory Drawer is the primary saved-signal revisit surface in Home. It should group signals into emotional/memory sections, keep search/filters secondary, open signals in a full-width reflective detail, and persist still-alive/changed-shape/not-anymore feedback as `targetType: "signal"`.
- Top of Mind needs an explicit internal-frequency / ambient-signal layer above individual graph nodes. It should answer what kind of city, room, peer group, standard, anti-environment, or self-image the user is trying to live near, not just rephrase a context node with ambition-flavored copy.
- Top-of-mind note surfaces expose `ambientSignal`, `matchedEnvironment`, `antiEnvironment`, and `evidenceRationale`; graph refresh stores those fields in the legacy `wow_moments.why` text until dedicated note persistence exists, and serializers split them back out for the API/UI.
- Primary Top of Mind post-it text should read like first-person jotting from the user's own scratchpad, but it should be direct and credible. Prefer "I need...", "I want...", and "I am done with..." over second-person diagnosis or weak hedges such as "I think", "maybe", "might", "probably", or "seems".
- Top-of-mind compatibility serialization should rewrite legacy second-person primary text and embedded ambient-signal fields into direct first-person post-it text instead of preserving old outside-voice copy.
- Primary user-facing architecture should stay inside one reflective world: Capture, five Top of Mind post-its, Memory Drawer, Share, and dev-only Internal Debug. Avoid reintroducing dashboard/archive/graph terminology into the main Home surface.
- When enough context exists, Home and share Top of Mind surfaces should render exactly five post-it slots where meaningful notes are available; empty or pulled-down slots should not be filled with weak placeholders.
- Context memory movement is currently derivable in `packages/api/src/lib/memory-movement.ts` from existing meaning node/evidence fields; Top of Mind refresh should rank by memory movement (`reactivated`, `contradicted`, `needs_testing`, etc.) as well as graph weight.
- Ambition synthesis is a bounded layer after deterministic Top of Mind ranking: use `packages/api/src/lib/ambition-synthesis.ts` for trigger gating, compact evidence inputs, prior feedback/rewrites, rejected alternatives, generic-output rejection, and deterministic fallback.
- Shareable Top of Mind surfaces can show generated post-its and provenance counts, but raw saved-signal text should stay private until an explicit sharing permission model exists.
- Internal context debugging should use `/api/admin/meaning-graph` as the diagnostic surface for memory movement, synthesis quality, Top of Mind provenance, and user corrections; keep this admin-only and out of the primary user experience.
- Primary Top of Mind post-it text should use compressed sticky-note thought language, usually 3-9 words and no more than 12, without forced `I need`/`I want`/`I am done with` starts; keep memory/status metadata in peel-open detail or internal debug, not on the visible card.
- Memory Drawer constellation relationships are currently derived in Home from saved-signal overlap in related Top of Mind notes, context terms, relevance reasons, and matching snippets; relationship feedback is stored as `targetType: "signal"` with `relationship_feedback:v1` correction text until a dedicated relationship feedback target exists.
- Top-of-mind primary text should be compressed but interpretable, usually 6-14 words, with a concrete ambition object plus a reason, contrast, or tension; reject ultra-short slogans such as "public before perfect", "taste as default", "test it outside", and "courage normal".
- Memory Drawer should stay as two modes inside Home: chronological List and relationship Canvas. Do not reintroduce memory-movement sections, dense sidebars, search-first structure, or graph/admin vocabulary into this user-facing revisit surface.
- Top of Mind action checklist items should be generated from post-it evidence, ambient/environment fields, and ambition dimension. Reject generic reflective homework such as "do one tiny test", "explore", "journal", "learn more", or actions that simply repeat the post-it title.
- Action recommendation state currently persists through `feedback` rows with `source: "action_recommendation"` and metadata keyed to the source top-of-mind note; use `/api/action-recommendations` rather than frontend-only action helpers.
- Home primary navigation should be object-led inside the wall: no persistent topbar, date display, or mode tabs; enter Memory Drawer through the physical drawer object and keep language switching as a quiet footer control.
- Memory Drawer default landing should be an object-led grouping desk: WAKA-proposed and user-created group objects sit above immutable raw saved signals, with chronological all-saves kept as a clean path and search as a secondary command.
- Memory Drawer inspiration comparison should happen through draggable `.memory-window` cards layered over the drawer desk; raw saved inspiration remains dominant, with only gentle nearby-pile and relationship context.
- Opened Memory Drawer groupings support Grid, Vertical Flow, and Horizontal Flow views; Flow mode should use clipped/aspect-ratio stages and transform movement, with draggable comparison windows still layered above the drawer desk.
- Top of Mind correction should use the wall metaphor: edit/pin the post-it wording or pull it down, persist through `/api/feedback`, and avoid visible true/partly/not-this reaction controls on user-facing note surfaces.
- Capture UI should call saved things inspirations and avoid internal/clinical terms such as signal, graph, node, memory movement, resonance, and analysis; quick save should feel safe first, with deeper reflection optional.
- Home user-facing surfaces should sanitize backend-provided Top of Mind, evidence, and action copy before rendering so internal terms such as signal, graph, node, resonance, analysis, and AI do not leak outside admin/debug surfaces.
- Main wall actions are independent paper objects: keep the action checklist visible and draggable on the wall whenever meaningful actions exist, even if Top of Mind notes are empty or the drawer UI changes.
- Memory Drawer should open to one clean white workspace with quiet grouping/all-inspirations entry objects; selecting one swaps to that focused card workspace with a small way back, rather than stacking grouping navigation and long card lists in separate vertical sections.
- Opened Top of Mind post-its should stay minimal: post-it text, one short explanatory paragraph, private-drawer evidence handoff, and physical edit/pull-down controls only.
- Capture highlight controls should be proximity-based inside the writing area; selected text gets an inline add-highlight popover and saved highlights expose nearby edit/remove/reason controls instead of detached bottom lists.
- Memory Drawer stack cards should stay neutral and evidence-like: white/off-white slips, quiet source/date metadata, no folder/icon chrome, no type badges, and no legacy colorful `memory-signal-card--*` treatment inside `.memory-drawer-stack`.
- Opened-inspiration highlight reactions currently persist on `inspiration_sparks.note` as `highlight_reaction:v1:{...}` metadata; capture-save highlight reactions still use `capture_metadata:v1:{...}` on the primary spark.

## 2026-07-07 - Group Top of Mind: surface more than one note

- Symptom: group board showed only 1 synthesized note.
- Cause: synthesis tried only 8 triggers (MAX_TRIGGERS) selected purely by
  wow_score, which clustered on the most prolific member; the ToM judge is
  deliberately selective (~1 in 8 triggers yields a note), so 8 triggers → 1.
- Fix: raise MAX_TRIGGERS to 24 and interleave triggers round-robin across
  members (PER_MEMBER_TRIGGER_CAP=8) so cross-member combinations get a fair
  chance. Also removed the deprecated US-051 group conversation-rooms card from
  the personal wall (gated off), and serialize group notes in the note's own
  generation locale with a title fallback so notes are never filtered for an
  empty localized title.
- Verified: re-synthesis on the real "Waka" group produced 7 notes (18 triggers,
  6 new + 1 existing) spanning Yunji, Jae Gyu Lee, Se One Park, agikee23, 젭재규;
